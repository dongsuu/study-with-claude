실행 컨텍스트 · 호이스팅 · TDZ

"코드가 실행되기 전에 엔진이 무엇을 준비하는가"를 스펙 수준으로 정리합니다. 다음 세션의 클로저는 여기서 다루는 [[Environment]] 하나로 설명됩니다.

개념 20~30분 → 확인 질문 → 문제 풀이 → 피드백

01실행 컨텍스트란?

JS 엔진이 코드를 실행하는 데 필요한 환경 정보를 묶은 단위입니다. 아래 시점에 만들어져 콜 스택에 쌓입니다.

  • 전역 코드나 모듈 코드를 평가할 때
  • 함수를 호출할 때 (선언할 때가 아님)
  • eval을 실행할 때

ES2015 이후 스펙 기준으로 실행 컨텍스트가 가진 핵심 정보입니다.

  • LexicalEnvironment: 식별자와 값의 바인딩을 저장하는 Environment Record와, 바깥 레코드를 가리키는 [[OuterEnv]] 참조
  • VariableEnvironment: var 선언용. 대부분 LexicalEnvironment와 같다고 봐도 됩니다.
  • this 바인딩: 함수라면 Function Environment Record 안에 있습니다. (W2에서 자세히)

식별자를 찾을 때는 현재 레코드부터 [[OuterEnv]]를 따라 바깥으로 올라갑니다. 이것이 스코프 체인입니다.

const x = 'global';
function outer() {
  const y = 1;
  function inner() {
    const z = 2;
    console.log(x, y, z);
  }
  inner();
}
outer();

inner() 실행 중의 스코프 체인

inner ERz: 2
[[OuterEnv]]
outer ERy: 1inner: ƒ
[[OuterEnv]]
Global ERx: 'global'outer: ƒ
→ null

핵심. 바깥 스코프는 "호출한 곳"이 아니라 "함수가 정의된 곳"입니다. 함수 객체는 만들어질 때 그 시점의 환경을 내부 슬롯 [[Environment]]에 저장해 둡니다. 호출되면 새 Environment Record를 만들고 그 [[OuterEnv]]를 저장해 둔 [[Environment]]로 연결합니다. 이것이 렉시컬 스코프이고, 다음 세션에서 다룰 클로저의 정체입니다.

const x = 'global';
function a() { console.log(x); }
function b() { const x = 'b'; a(); }
b();
결과 보기
'global'a의 [[Environment]]는 정의된 위치인 전역입니다. 호출한 b의 스코프와는 아무 관계가 없습니다.

02호이스팅의 실체: 끌어올림이 아니라 먼저 등록

코드는 실제로 위로 옮겨지지 않습니다. 엔진은 스코프의 코드를 실행하기 전에 선언 인스턴스화 단계를 거쳐 그 스코프의 모든 선언을 Environment Record에 먼저 등록합니다. 선언 종류마다 다른 것은 초기화 여부입니다.

핵심. let/const도 호이스팅됩니다. 바인딩은 미리 만들어지고 초기화만 되지 않은 상태입니다. 같은 이름의 var와 function이 함께 있으면 선언 단계에서는 함수가 우선하고, 이후 실행 단계의 할당문이 값을 덮어씁니다. 선언과 할당은 서로 다른 단계입니다.

03TDZ (Temporal Dead Zone)

바인딩이 만들어진 시점부터 선언문이 실행되어 초기화되는 시점까지의 구간입니다. 이 구간에 접근하면 ReferenceError가 납니다. 이름에 Temporal(시간적)이 붙은 이유는, 코드상의 위치가 아니라 실행 시점의 문제이기 때문입니다.

function read() { return v; } // 위치상으로는 선언보다 위
const v = 1;
console.log(read());
결과 보기
1read가 호출되는 시점에는 v가 이미 초기화되어 있습니다.

TDZ가 생각보다 자주 드러나는 곳

  • typeof도 안전하지 않습니다. 선언되지 않은 변수는 'undefined'를 돌려주지만, TDZ에 있는 변수는 에러가 납니다.
  • 기본값 매개변수: 매개변수도 왼쪽부터 순서대로 초기화됩니다. function f(a = b, b) {}에서 f()를 호출하면 에러가 납니다.
  • shadowing: 블록 안에서 같은 이름을 let으로 선언하면, 블록이 시작되는 순간부터 바깥 변수가 가려집니다.
  • class: class 선언도 TDZ가 적용되므로 정의하기 전에 new할 수 없습니다.
console.log(typeof notDeclared);
console.log(typeof later);
let later = 1;
결과 보기
'undefined' ReferenceError: Cannot access 'later' before initialization

04전역 스코프의 특이한 점

전역 Environment Record는 두 부분으로 이뤄져 있습니다.

  • Object Record: var, function 선언이 들어갑니다. 그래서 window의 프로퍼티가 됩니다.
  • Declarative Record: let, const, class 선언이 들어갑니다. 그래서 window에 없습니다.
var a = 1;   // window.a → 1
let b = 2;   // window.b → undefined

여러 <script> 태그는 전역 스코프를 공유합니다. 서로 다른 스크립트에서 같은 이름을 let으로 선언하면 SyntaxError가 납니다. ES 모듈은 파일마다 자체 모듈 스코프를 가지므로 이런 충돌이 없습니다.
